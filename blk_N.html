תקלות בדרך

תקלה 1: Request Timeout אחרי החלפת השורה. מיד אחרי ההחלפה, הגלישה מ-PC-HOME נכשלה ב-Request Timeout. בדקתי לפי הסדר:

  • מהנתב, telnet 192.168.40.11 80 החזיר Open, כלומר שרת ה-Web עונה על פורט 80.
  • ב-debug ip nat ראיתי שהבקשות מ-200.0.0.20 מגיעות לנתב ומתורגמות ל-192.168.40.11, אבל אין אף שורה בכיוון ההפוך. התשובה של השרת לא תורגמה חזרה.
  • החזרתי זמנית את השורה ל-192.168.40.10, וגם זה לא עבד, אף על פי שעבד שעה קודם. מכאן שהבעיה לא בשרת ולא בהגדרה, אלא במצב הפנימי של ה-NAT בנתב אחרי שהחלפתי תרגום קבוע תוך כדי ריצה.

תל אביב: debug ip nat. רואים רק את הכיוון הנכנס (200.0.0.20 ← 192.168.40.11), בלי תרגום של התשובות

תל אביב: telnet לפורט 80 של השרת מחזיר Open, השרת עצמו תקין

הפתרון היה לשמור את ההגדרות (write memory), לשמור את הקובץ, ולסגור ולפתוח מחדש את Packet Tracer. הנתב עלה עם ההגדרה השמורה, והגלישה עבדה מיד. בציוד אמיתי הפקודה clear ip nat translation * הייתה אמורה להספיק; ב-Packet Tracer היא לא עזרה. המסקנה שלי: אחרי שינוי של תרגום קבוע ב-Packet Tracer צריך לשמור ולהעלות את הנתב מחדש לפני שבודקים.

תקלה 2: שרת ה-Web הפסיק לענות. אחרי עריכת הקובץ index.html, השרת ענה ל-ping אבל גלישה אליו נכשלה אפילו משרת אחר באותו VLAN. כיבוי והדלקה של שירות ה-HTTP בשרת (Services ← HTTP ← Off ואז On) החזירו אותו לעבודה.
