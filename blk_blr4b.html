R-1 ו-R-2: היציאה מהסניף

שני הנתבים כבר החזיקו BGP מול R-ISP-1, אבל לא היה להם מה לפרסם. עכשיו הם מפרסמים את כל הבלוק של הסניף בשורה אחת:

! R-1
ip route 0.0.0.0 0.0.0.0 10.0.0.13
ip route 0.0.0.0 0.0.0.0 172.19.10.3 10
ip route 172.19.0.0 255.255.0.0 Null0
router bgp 65004
 network 172.19.0.0 mask 255.255.0.0
!
access-list 110 remark NAT - only traffic to the internet
access-list 110 deny ip any 10.0.0.0 0.255.255.255
access-list 110 deny ip any 172.16.0.0 0.15.255.255
access-list 110 deny ip any 192.168.0.0 0.0.255.255
access-list 110 permit ip 172.19.0.0 0.0.255.255 any
interface Serial0/1/0
 ip nat outside
ip nat inside source list 110 interface Serial0/1/0 overload
!
! R-2
interface GigabitEthernet0/0/0.10
 ip address 172.19.10.3 255.255.255.0
 ip nat inside
ip route 0.0.0.0 0.0.0.0 10.0.0.17
ip route 172.19.0.0 255.255.0.0 172.19.10.2
router bgp 65004
 network 172.19.0.0 mask 255.255.0.0
! ... same access-list 110 and overload line
  • הנתיב ל-Null0: פקודת network ב-BGP מפרסמת רשת רק אם היא מופיעה בטבלת הניתוב בדיוק באותה מסכה. בטבלה של R-1 יש חמש רשתות של ‎/24, ואין ‎/16. הנתיב ל-Null0 יוצר את השורה הזאת, וגם זורק חבילות לרשתות בבלוק שלא קיימות, כמו שהוסבר בפרק סיכום הנתיבים. הרשתות האמיתיות לא נפגעות, כי שורה מדויקת יותר תמיד מנצחת.
  • שני נתיבי Default ב-R-1: הראשי אל הספק. השני, עם Administrative Distance של 10, אל R-2. הוא נכנס לטבלה רק אם הקו של R-1 לספק נופל.
  • R-2: אין לו תתי-ממשקים למחלקות, ולכן הוא מגיע אליהן דרך R-1, בנתיב סטטי לכל הבלוק. אותו נתיב גם מאפשר לו לפרסם את הבלוק ב-BGP.
  • ה-NAT: כמו בשאר הסניפים, ה-ACL שולל קודם את כל היעדים הפרטיים. לכן תעבורה מבנגלור לסניפים אחרים יוצאת עם הכתובת המקורית, ורק תעבורה לאינטרנט מתורגמת.

בנגלור: טבלת ה-BGP ב-R-1. הבלוק 172.19.0.0/16 נוצר כאן (Next Hop של 0.0.0.0), ושאר הרשתות נלמדו מהספק

השרתים ותחנות הקצה

בשרתים הכתובת קבועה. בחלון IP Configuration יש שני חלקים נפרדים, ל-IPv4 ול-IPv6, ומילאתי רק את העליון. בשרת ה-DHCP הוספתי גם מאגר של IPv4 לחדר השרתים: שער 172.19.10.1, ‏DNS בכתובת 172.19.10.11, והחלוקה מתחילה ב-172.19.10.100, כדי לא להתנגש בכתובות הקבועות.

בנגלור: המאגר של IPv4 בשרת ה-DHCP, לצד מאגר ה-DHCPv6 שכבר היה בו

בנגלור: המחשב הנייד בחדר השרתים. למעלה כתובת IPv4 מהשרת, למטה כתובת IPv6, ושתי הבקשות הצליחו

ב-48 המחשבים של המחלקות סימנתי DHCP בחלק של IPv4. כאן אין בעיית Relay כמו שהייתה ב-DHCPv6: הנתב R-1 הוא גם השער וגם שרת ה-DHCP, והוא עונה לכל מחלקה מהמאגר שמתאים לתת-הממשק שממנו הגיעה הבקשה.

בנגלור: DEV-01 קיבל 172.19.20.11 מ-R-1, וכתובת ה-IPv6 שלו נשארה

בנגלור: ipconfig ב-DEV-01. שתי כתובות ושני שערים, FE80::1 ו-172.19.20.1

בנגלור: סוף הפלט של show ip dhcp binding ב-R-1. בסך הכול 48 כתובות, 12 בכל מחלקה

בשני מחשבים הופיעה לרגע ההודעה DHCP request failed, ואחרי כמה שניות הם קיבלו כתובת לבד: הבקשה הראשונה אבדה, והמחשב ניסה שוב.
