בדיקה עם לקוח אלחוטי

כדי לבדוק את הרשת מקצה לקצה הוספתי לאזור של RND לפטופ בשם USA_Samsung_F2-LAPTOP-WIFI. לפטופ ב-Packet Tracer מגיע עם כרטיס רשת קווי, ולכן החלפתי אותו בכרטיס אלחוטי:

  1. בלשונית Physical מכבים את הלפטופ בכפתור ההפעלה.
  2. גוררים את כרטיס הרשת הקווי החוצה מהמכשיר, אל רשימת המודולים.
  3. גוררים למקומו את המודול WPC300N, כרטיס אלחוטי בתדר 2.4GHz.
  4. מדליקים את הלפטופ.

אחר כך, ב-Config ‎> Wireless0, מגדירים את שם הרשת (SSID), ‏Authentication = WPA2-PSK, הסיסמה, ‏Encryption = AES, ו-IP Configuration = DHCP. הלפטופ מתחבר לבד לנקודת הגישה שמשדרת את ה-SSID הזה.

הלפטופ אחרי ההחלפה: הכרטיס האלחוטי WPC300N במקום הכרטיס הקווי

רשת העובדים: עם Samsung-Staff הלפטופ התחבר לנקודת גישה של רשת העובדים וקיבל משרת ה-DHCP את הכתובת 172.17.200.10, מהמאגר של VLAN 200. זה מראה שכל השרשרת עובדת: נקודת הגישה, הפורט שלה ב-VLAN 200, ה-Trunk עד MLS-SRV, ה-SVI וה-helper-address.

הלפטופ ברשת העובדים: Samsung-Staff, ‏WPA2-PSK, והכתובת 172.17.200.10 מ-DHCP

מהלפטופ שלחתי ping לאינטרנט (8.8.8.8) ולשרת האתר הפנימי (172.17.130.12). שניהם ענו. עובד שמחובר באלחוט מגיע לשרתים, כמו ממחשב קווי.

רשת העובדים: ping לאינטרנט ולשרת הפנימי

רשת האורחים: שיניתי בלפטופ את שם הרשת ל-Samsung-Guest ואת הסיסמה ל-SamsungGuest26. הלפטופ עבר לנקודת הגישה של SALES וקיבל את הכתובת 172.17.205.10, מהמאגר של VLAN 205.

הלפטופ ברשת האורחים: Samsung-Guest והכתובת 172.17.205.10 מ-DHCP

ה-ping לאינטרנט (8.8.8.8) עבר. ה-ping לשרת פנימי (172.17.130.10) נחסם: השער של האורחים, 172.17.205.1, החזיר Destination host unreachable. זו השורה deny ip any 172.17.0.0 0.0.255.255 ב-ACL ‏GUEST-IN. האורח מקבל אינטרנט ולא מגיע לציוד של החברה, כמו שתוכנן.
